# MedSim Frontend

Frontend-часть платформы `MedSim` для учебной ролевой симуляции работы медицинской организации. Интерфейс покрывает вход игрока, комнату ожидания, рабочее пространство команды, панель ведущего, настройку сессии, мониторинг команд, чат, канбан, экономику и стартовый склад.

## Быстрый Запуск

### Весь стек через Docker Compose

Полный стек запускается из backend-репозитория, потому что там лежит общий `docker-compose.yml`.

```bash
cd MedSim_back
cp .env.example .env
docker compose --env-file .env up --build -d
```

После запуска frontend доступен на:

- `http://localhost:5173`

Остановка:

```bash
cd MedSim_back
docker compose down
```

### Только frontend для разработки

Backend должен быть запущен отдельно на `http://127.0.0.1:8080`.

```bash
cd MedSim_front
npm install
npm run dev
```

Vite dev server обычно открывается на:

- `http://localhost:5173`

## Сборка

```bash
cd MedSim_front
npm run build
```

## Backend API

По умолчанию frontend обращается к backend через относительные пути:

- `/api`
- `/ws/team-chat`

В режиме разработки `Vite` проксирует их на `http://127.0.0.1:8080`. В Docker-режиме `Nginx` проксирует эти же пути на backend-контейнер.

Если нужно указать backend вручную, можно использовать:

```env
VITE_API_BASE_URL=http://localhost:8080
```

## Что Реализовано

### Игрок

- Ввод имени и реальной должности.
- Список доступных сессий для подключения.
- Автоматический выбор сессии, если доступна только одна игровая комната.
- Повторный вход в уже начатую игру по тем же имени, должности и выбранной сессии.
- Подключение к уже запущенной игре: новый игрок попадет в нераспределённые, пока ведущий не назначит ему команду и роль.
- Комната ожидания до старта, при паузе и после завершения игры.
- Автоматический переход в рабочее пространство команды после запуска.
- Жесткая блокировка игровых разделов при паузе и после завершения сессии.
- Отдельное пространство только своей команды без чужих составов и чужих карточек.
- Выезжающее боковое меню с переключением между разделами игрока.
- Блок с этапом, режимом и таймером.
- Командный чат с историей и обновлениями в реальном времени.
- Блок уведомлений по канбану и верхний баннер при новых уведомлениях.
- Просмотр карточек текущего этапа как на канбан-доске, так и в плоском списке для чат-раунда.
- Переключатель видимости: только свои карточки или все доступные карточки команды.
- Мобильная канбан-доска по одной колонке за раз со стрелками переключения.
- Раскрытие карточки с деталями, вариантом решения, ресурсами и историей.
- Выбор способа решения задачи исполнителем.
- Действия исполнителя: взять в работу, выбрать решение и отправить на согласование.
- Действия главврача: выставить приоритет, выбрать подразделение, вернуть карточку в общий пул, финально согласовать решение.
- Действия главной медсестры и главного инженера: назначить исполнителя, вернуть карточку в общий пул, отложить задачу на следующий этап.
- Экран главврача с планом кабинетов, экономикой, задачами и итогами этапов.
- Отображение склада только руководящим ролям.

### Ведущий

- Вход по `Basic Auth`.
- Выезжающее боковое меню с отдельными разделами управления сессией.
- Создание сессии с названием, количеством команд, стартовым бюджетом и ресурсом времени.
- Просмотр, переименование, запуск, пауза, продолжение, завершение, перезапуск и удаление сессии.
- Настройка команд, ролей, этапов, склада и экономики в отдельных разделах.
- Случайное распределение игроков по командам.
- Ручной перенос игроков между командами и в состояние без команды.
- Исключение лишних участников из сессии.
- Переименование команд.
- Случайное и ручное распределение игровых ролей.
- Настройка длительности и режима этапов.
- Автоматическое равномерное распределение задач по этапам.
- Ручное распределение количества задач по этапам.
- Настройка стартового склада до старта.
- Случайная генерация общего стартового склада для всех команд.
- Просмотр ресурсов всех команд и применение штрафов по бюджету и времени.
- Мониторинг команд после старта.
- Отдельный live-дашборд по выбранной команде с таймером, горизонтальной картой больницы и канбаном или списком проблем в зависимости от этапа.
- Отдельный раздел с составом команд и ролями.
- Отдельный раздел с чатами обеих команд.
- Послеигровая аналитика с экспортом в `Excel`.
- Управление активным этапом и общим таймером.

## Игровые Экраны

### Канбан

Фронт отображает backend-статусы как игровые колонки и секции:

- `REGISTERED` и `REWORK` — колонка `Задачи этапа`.
- `ASSIGNED` и `READY_FOR_WORK` — колонка `На распределении`.
- `IN_PROGRESS` — в процессе.
- `DEPARTMENT_REVIEW` и `CHIEF_DOCTOR_REVIEW` — колонка `На согласовании`.
- `DONE` — колонка `Готово`.
- `HOLD` — отдельный блок отложенных задач вне основного потока.

Поведение карточек в интерфейсе:

- главврач разбирает задачи этапа и отправляет их в подразделение;
- руководитель подразделения назначает исполнителя;
- исполнитель выбирает способ решения и двигает карточку дальше;
- руководители могут вернуть карточку в общий пул;
- `HOLD` показывается отдельно и после перехода на следующий этап задача возвращается в пул;
- неуспешная попытка решения подсвечивается для главврача и требует повторного решения.

На телефоне канбан показывает одну колонку за раз, чтобы карточки не превращались в микроскопическую таблицу. Между колонками можно переключаться стрелками сверху.

### Экономика

В интерфейсе показываются:

- текущий баланс команды;
- ресурс времени этапа;
- зарезервированные деньги и время;
- доступные ресурсы с учетом резервов;
- складские резервы;
- доходы, расходы, штрафы и бонусы;
- итоги этапов;
- последние события экономики.

Резерв создается, когда исполнитель выбирает способ решения. Списание происходит только после финального согласования главврачом.

### Склад

До старта ведущий видит общий стартовый склад с количеством каждой позиции. Он может сохранить ручные значения или заново сформировать случайный склад.

После старта склад видят только руководящие роли команды. Исполнители склад не видят, но при выборе способа решения видят доступность варианта по ресурсам.

## Мобильный Сценарий

Основной игровой сценарий рассчитан на телефоны:

- крупные кнопки и поля;
- секции можно сворачивать;
- длинные карточки раскрываются по нажатию;
- канбан на телефоне показывает одну колонку за раз;
- боковое меню позволяет быстро переключаться между разделами без длинной прокрутки;
- уведомления показываются отдельным блоком и коротким баннером сверху;
- у ведущего интерфейс тоже адаптивный, но основной сценарий ведущего удобнее на ноутбуке.
